## 1. 받아쓰기 보정 모델 비교

**결론: 서버 교정 뒤에 언어 모델을 붙이면 소음·현장 조건 10개 모두에서 지금보다 같거나 좋아졌습니다. Haiku 5.5는 오류율이 가장 낮고 빠르며, GPT-6 Luna는 문장을 틀리게 바꾸는 일이 절반 이하이고 서비스가 이미 쓰는 키로 붙일 수 있습니다. 로컬 모델 LFM3 1.7B는 오히려 나빠져 후보에서 뺍니다.**

### 1.1 시험 방법

| 항목 | 내용 |
|---|---|
| 데이터 | 조용한 녹음 180문장, 소음 합성 7조건(웅성거림 20/10/5/0 dB, 옆 사람 10/5/0 dB), 경복궁 현장 녹음 2개(126초) |
| 받아쓰기 | 저장해 둔 Amazon Transcribe 결과 (위치별 단어집) |
| 서버 교정 | 지금 서버 코드 그대로 (자주 틀리는 표기 표 + 위치별 교정 사전) |
| 언어 모델 | LFM3 1.7B (로컬), Claude Haiku 5.5 (Claude API), GPT-6 Luna (OpenAI API). 셋 다 같은 지시문과 같은 위치별 용어 목록을 넘김 |
| 호출 설정 | 추론 끔, 답은 JSON 한 칸(고친 문장)으로 강제. GPT-6 Luna는 서비스(gunggeum-ai-llm-gps)와 같은 방식(Responses API)으로 부름 |
| 순서 | "서버 교정 → 언어 모델", "언어 모델 → 서버 교정" 두 가지 |

### 1.2 결과

- **'임진왜란' 오인식은 두 모델 모두 고쳤습니다.** 조용한 녹음의 "임진왜한테 소실됐다가"가 Haiku 5.5는 "임진왜란 때 소실됐다가", GPT-6 Luna는 "임진왜란에 소실됐다가"로 바뀌었습니다.
- **답 모양을 강제해야 안정적이었습니다.** Haiku 5.5는 강제하기 전에 고친 문장 대신 설명을 내놓는 출력이 29건 있었고, 강제하자 사라졌습니다.
- **순서는 서버 교정을 먼저 두는 쪽이 대체로 좋았습니다.** 조용한 녹음에서 Haiku 5.5는 2.87% 대 2.92%, GPT-6 Luna는 3.20% 대 3.28%였습니다.
- **LFM3 1.7B는 순서와 상관없이 지금보다 나빠졌습니다.** 용어 목록을 문장에 쏟아내거나 문장을 다시 쓰는 출력이 많았습니다.

### 1.3 모델을 고를 때 볼 숫자

| 항목 | Haiku 5.5 | GPT-6 Luna |
|---|---|---|
| 단가, 입력 / 출력 (달러/100만 토큰) | 0.10 / 0.50 | 0.10 / 0.50 |
| 문장당 비용 (달러) | 약 0.00008 | 약 0.00004 |
| 문장당 추가 시간, 평균 / p90 (초, 조용한 녹음) | 1.35 / 1.55 | 1.74 / 1.98 |
| 서버에 필요한 것 | Claude API 키를 새로 둠 | 서비스가 이미 쓰는 OpenAI 키 |

- 문장당 비용은 이번 측정의 토큰 수로 계산했습니다. 같은 문장에도 GPT-6 Luna가 받는 입력 토큰이 Haiku 5.5의 절반쯤이었습니다.
- 자막은 지금 말이 끝난 뒤 약 0.7~1.1초에 도착합니다. 보정을 붙이면 여기에 위 시간이 더해집니다.

## 2. 공지 자동 번역 (gunggeum-be 이슈 16번, PR 19번)

**결론: 공지 예문 30개에서 찾은 문제 8가지 중 7가지가 백엔드 PR 19번에 들어갔고, 공지 30개와 해설 300문장을 다시 재서 나빠진 곳 없이 고쳐진 것을 확인했습니다. 리뷰에서 요청한 두 가지(괄호가 겹치는 표기, 기간 끝 날짜)도 반영되어 승인했습니다.**

공지 자동 번역과 실시간 자막은 같은 번역 코드(`api/app/live/translate.py`)를 씁니다. 1·7·8번은 자막에도 적용되고, 2~5번은 공지 번역에서만 켜집니다.

**다시 잰 결과 (공지 예문 30개, 해설 300문장, 영어·태국어, Amazon Translate)**

| 항목 | 고치기 전 (develop) | PR 19번 |
|---|---|---|
| 공지 용어 표기 일치 (%, ↑ 높을수록 좋음), 영어 / 태국어 | 79.3 / 79.5 | 100 / 100 \* |
| 공지 한글이 남은 칸 (개, ↓ 낮을수록 좋음) | 2 | 0 |
| 해설 300문장 용어 일치, 묶음 제외 (%, ↑) | 96.0 | 96.0 |
| 태국어 연도 보존 (85개 중, ↑) | 78 | 85 |
| 태국어 연도 표기가 잘린 문장 (개, ↓) | 11 | 0 |

\* 일부러 감싸지 않은 6건(태풍 "대비", "조정됩니다")은 뺐습니다. 넣으면 영어 86/92, 태국어 77/83입니다.

**문제별 상태**

| 번호 | 문제 | 고치기 전 → PR 19번 (영어) | 상태 |
|---|---|---|---|
| 1 | 줄바꿈·기호 뒤 용어를 못 찾음 | "Gyeonghoe-ro" → "Gyeonghoeru (Banquet Pavilion)" | 고쳐짐 |
| 2 | 흔한 낱말이 용어로 바뀜 | "Daebi (Queen Dowager) controls part of the viewing route" → "in preparation for Typhoon No. 14" | 고쳐짐. "관람 시간 조정 안내"의 '조정'은 아직 마당 이름으로 바뀜 |
| 3 | 꺾쇠 머리말이 한글로 남음 | "&lt;긴급&gt;Commentary…" → "&lt;Urgent&gt; Full cancellation…" | 고쳐짐 |

| 8 | 연도가 지어내지는 문장 | "2015년" → "1967" → 다시 번역해 "2015" | 고쳐짐 |

- 괄호가 겹치는 표기는 괄호 안을 로마자 이름만 쓰도록 바뀌었습니다("사정전(편전)" → "Sajeongjeon (Royal Council Hall) (Pyeonjeon)").
- 2번은 대비·부재·조회 3개만 빼는 방식입니다. 장소 분류를 넣어도 '조정'(마당 이름이면서 일반 낱말)은 가릴 수 없어, AI 쪽에서 "공지에서 감싸지 않을 용어" 목록을 드리기로 했습니다.
- 기간 끝 날짜 처리가 "1~1.5배" 같은 숫자를 "1~1월 5일배"로 바꾸는 경우가 있습니다. 공지 예문에는 없는 꼴이라 이번 PR은 승인했고, 이후에 범위를 좁히면 됩니다.
- 태국어는 기계 채점(한글·표시 남음, 용어 표기)을 모두 통과했습니다. 문장이 자연스러운지는 팀에 태국어를 읽을 사람이 없어 확인하지 못했습니다.

## 3. 번역 용어 표 정비

번역 용어 표(`translate_terms.csv`, 332줄)는 용어 엑셀·전각 엑셀과 일반 단어 목록을 합쳐 만듭니다. 세 가지를 손봐야 합니다.

### 3.1 일반 단어 21개 추가

**결론: 용어 엑셀의 선정 기준("외국인이 이해하기 어려운 개념·건축·역사 용어")에서 빠진 사람 이름, 흔한 낱말, 용어에 말이 붙은 이름 21개를 일반 단어 목록에 넣습니다. 영어·태국어 표기 초안은 만들었습니다.**

| 나오는 곳 | 낱말 | 지금 생기는 일 |
|---|---|---|
| 공지 | 광화문광장, 경복궁역 | 앞부분만 용어로 바뀜 (이슈 16번 6번) |
| 해설 자막 | 세종, 정도전, 장영실, 세종실록, 사바틴, 안사고, 홍례문, 추수부용루 등 | 태국어 자막에 영어로 남음 |
| 해설 자막 | 임금 | 태국어로 '급여(ค่าจ้าง)'로 번역됨 (20번 중 5번) |
| 해설 자막 | 종친부, 내소주방, 서행각, 진찬의궤, 물익공, 사대부가, 조선총독부미술관 | 앞부분만 용어로 바뀜 |
| 둘 다 | 경복궁, 왕, 왕비 | 영어는 있으나 태국어 칸이 비어 있음 |

- 표기는 용어 엑셀과 같은 모양("로마자 (설명)")으로 썼습니다. 광화문광장은 서울시 공식 영어 이름 "Gwanghwamun Square"를 따랐습니다.
- 태국어는 태국어 위키백과에 문서가 있는 6개(경복궁, 경복궁역, 세종, 세종실록, 정도전, 장영실)를 그 표기로 맞췄고, 나머지 15개는 기존 표의 표기 방식에 맞췄습니다. 기존 태국어 329줄을 포함해 태국어 표기는 원어민 검수를 거치지 않았습니다.

### 3.2 묶음 표기 나누기 (안건 ②)

**결론: 한 줄에 여러 용어를 묶어 둔 표기 29종(60줄) 때문에 서버가 그 낱말들을 건너뛰고 있습니다. 낱말별로 나눈 초안은 만들었고, 어디서 나눌지만 정하면 됩니다. 나누면 태국어 용어집의 200바이트 한도 문제도 함께 풀립니다.**

| 지금 | 나눈 초안 |
|---|---|
| 창건 → Changgeon / Junggeon / Jaegeon / Bogwon / Sosil | 창건 → Changgeon (Original Construction) |
| 복원 → Changgeon / Junggeon / Jaegeon / Bogwon / Sosil | 복원 → Bogwon (Restoration to Original Form) |
| 국보 → Gukbo and Bomul (National Treasure and Treasure) | 국보 → Gukbo (National Treasure) |

- 해설 300문장의 채점 항목 772개 중 104개가 묶음 때문에 건너뛰어집니다.
- 나누면 Amazon Translate 용어집의 200바이트 한도를 넘던 태국어 8줄이 모두 한도 안(최대 167바이트)으로 들어옵니다.
- 같은 것의 다른 이름(세자/왕세자, 편액/현판 등 19줄)은 나누기만 하면 되고, 서로 다른 말을 묶은 것(창건/복원/소실, 국보/보물 등 41줄)은 낱말마다 설명을 새로 썼습니다.

| 어디서 나눌지 | 장점 | 걸리는 점 |
|---|---|---|
| 원본 엑셀(`경복궁_용어.xlsx`)에서 | 카드·답변·자막이 같은 표기 | 용어 카드와 llm-gps 답변 DB에도 영향 → 카드·답변 담당과 맞춰야 함 |
| 번역용 표를 만들 때만 | 카드에 영향 없음, AI 저장소 안에서 끝남 | 자막에서 "Bogwon"을 눌러도 열리는 카드 제목은 묶음 이름 |

함께 정할 것: 별칭 3줄(조대비·옥당·익종)을 추가할지. 지금은 표에 없어 번역기가 옮깁니다.

### 3.3 동사로 쓰인 용어 (안건 ③)

**결론: 용어 뒤에 '하다·되다'가 붙어 동사로 쓰이면(승하했다, 훼철됐다) 지금은 이름 표기가 동사 자리에 들어가 자막이 어색합니다. 어려운 한자어를 쉬운 말로 바꿔 보내면 8문장 중 7문장이 자연스럽고 뜻도 맞게 나왔습니다.**

| 방식 | 뜻이 맞게 나온 문장 (8개 중, ↑) | 예: 문종은 1452년 천추전에서 승하했습니다 |
|---|---|---|
| 지금 (감쌈) | 8, 문장은 어색함 | … to Seungha (Passing of a Monarch) in 1452 |
| 감싸지 않고 그대로 보냄 | 2 | Moon Jong **won** Cheonchujeon in 1452 (승하 → 이기다) |
| 쉬운 말로 바꿔 보냄 (승하 → 사망) | 7 | Moon Jong **died** in 1452 at Cheonchujeon |

- 바꾼 말: 승하 → 사망, 훼철 → 철거, 집자 → 수집, 봉안 → 보관, 모사 → 복제. 대리청정은 "대리 통치"로 바꿔도 "victorious reign"으로 틀려 다른 말을 찾아야 합니다.
- 공지 번역에서는 동사로 쓰인 용어를 감싸지 않는 처리가 PR 19번으로 이미 들어갔습니다. 자막은 위 문제 때문에 따로 정해야 합니다.
- 3.2절과 이어집니다. 창건·복원·소실 등은 해설에서 대부분 동사로 쓰여(32번 중 21번), 묶음을 나누면 이 21곳도 같은 문제가 생깁니다. 이 낱말들은 번역기가 잘 알아서("restored", "destroyed") 감싸지 않기만 하면 됩니다.

## 4. 단어집 발음 표기 검수 (11/20 멘토 피드백)

**결론: Transcribe 단어집에는 글자 표기만 등록되어 있고, 발음 칸은 AWS가 지원을 끝내 검수 대상이 아닙니다.**

- 팀 계정에 등록한 단어집 72개(2,040줄)의 발음 칸(SoundsLike·IPA)과 표시 칸(DisplayAs)은 모두 비어 있습니다.
- AWS 공식 문서 기준으로 발음 칸은 지원이 종료되어, 값을 넣어도 무시됩니다.
- 숫자는 등록할 때 한글 읽기로 바꿨습니다(예: 중2층 → 중이층).
- 발표 때 "AI로 발음 기호를 매핑했다"고 답한 부분은 실제와 달라, 다음 멘토 보고 때 바로잡겠습니다.

### 막힌 점 / 해결

- **팀 AWS 계정의 Bedrock에서 GPT-6 Luna를 부르면 "이 계정에서는 쓸 수 없음"으로 거절됩니다.** IAM 권한 문제가 아니라 AWS가 계정에 모델을 열지 않은 상태입니다. 서비스가 쓰는 방식대로 OpenAI API로 직접 불러 측정을 마쳤습니다.
- **소리가 많이 뭉개진 조건(0~5 dB)에서는 Haiku 5.5가 연도를 바꾸거나 없던 문장을 덧붙인 경우가 있었습니다.** 약 2,900번 호출 중 4건입니다.
- **태국어를 읽을 사람이 팀에 없습니다.** 표기는 태국어 위키백과로 맞출 수 있는 것만 맞췄고, 번역 품질은 기계 채점으로만 확인하고 있습니다.
